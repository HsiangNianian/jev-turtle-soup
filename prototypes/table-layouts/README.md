# 同桌布局原型

已选定 **手机 A + 电脑 C**，并落实到 Web/PWA、SwiftUI iOS 和 Compose Android。正式行为与验证方式见 [同桌说明](../../docs/rooms.md)。这里保留设计比较，便于回看取舍。

独立的可交互设计稿，用于选择布局。直接打开 `index.html`，或在这个目录运行 `python3 -m http.server 4178 --bind 0.0.0.0`。不依赖构建、网络字体或线上 API。

| 方案         | 手机 / 原生 App                                            | 电脑网页                        | 取舍                                 |
| ------------ | ---------------------------------------------------------- | ------------------------------- | ------------------------------------ |
| A 会话优先   | 同一时间线容纳讨论和问答，输入框切换收件对象；汤面按需展开 | 居中的连续会话，案卷从右侧打开  | 社群感最直接，讨论多时需回看正式问答 |
| B 案卷翻页   | 案卷、推理、讨论各占整页，通过底部标签切换                 | 左侧页签，右侧完整内容页        | 信息分明，需要在页面间切换           |
| C 围桌工作台 | 推理为主屏，讨论从侧边拉出                                 | 案卷 / 成员、推理、讨论三列并排 | 桌面协作最强，手机讨论多一次操作     |

预览可切换 App / 手机网页 / 电脑网页、等待入座 / 已经开汤、墨色 / 纸色。等待时点「邀请朋友 → 模拟朋友入座 → 开始同桌」体验状态变化。正式提问与讨论有各自的演示草稿，支持输入和发送，汤面使用反馈截图里的真实长英文文本。

所有人物、在线状态、问题回答均为演示。不会调用 Jev、连接 WebSocket、发送真实邀请或写入游戏数据。原型中的 App 视图是 HTML 布局模拟；实际原生实现位于 `ios/` 和 `android/`。

「偏向这一版」仅保存在本机浏览器，不会自动发给开发者。比较截图位于 `previews/`。原型与正式页面源码独立，不会随当前网站部署自动进入线上路由。

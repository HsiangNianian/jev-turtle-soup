# 作者周报

每周一北京时间 **20:00**（UTC `0 12 * * mon`）发送作者过去一周的动态。首次启用后的计划发送时间是 2026-09-28 20:00。管理后台的「作者周报」可以预览、查看发送记录，以及手动发送或补发最近一期；「社群观察」仍单独保留。

## 收件人与统计

- 延续原作者周报范围：有公开作品、没有退订、统计期内有游玩、解开、点赞或留言的作者。无动态不发，作者自己的操作不计。
- 每期固定为上周一 20:00（含）至本周一 20:00（不含）。延迟执行和手动补发仍用同一期，避免跨周重复统计。游玩、解开沿用现有单人 attempts 统计，点赞和留言包括作品及作者主页。
- 使用作者的中文、英文或日文设置。邮件中的个人退订链接继续有效；预览使用占位链接，不生成或返回真实退订令牌。
- 收件作者按 ID 分页遍历，无旧版前 200 位作者的截断。

## 发送与重试

`digest_runs` 记录每期运行，`digest_deliveries` 用 `(period_end, uid)` 主键原子占位。Cron 重试、手动重复点击和并发调用都不会再次发送已有占位的邮件。邮件服务接收后记录 message ID；「已提交发送」不代表对方已收到或阅读。

明确的服务拒绝记为 `failed`，管理员可补发，每封最多尝试三次；补发沿用首次统计快照，并重新检查退订状态。未知网络错误记为 `uncertain`。执行中断留下的 `sending` 超过 15 分钟后在后台显示「结果待核查」。这两类不会自动重发，因为邮件可能已被服务接收，应先核对 Cloudflare 邮件日志。发送后的数据库写入失败同样保留占位，不把它当作邮件发送失败再次重发。

周报使用现有 `EMAIL` 绑定和 `MAIL_FROM`。调用使用 [Cloudflare Email Service Workers API](https://developers.cloudflare.com/email-service/api/send-emails/workers-api/)；该接口没有文档化的幂等键，因此不宣称跨邮件服务与数据库的 exactly-once 保证。单封失败不阻止其他作者发送，但整轮 Cron 会报告失败，在后台保留详情。

## 部署与检查

1. 先应用可重复执行的 `db/migrations/021-weekly-digest.sql`，再发布 Worker。
2. 确认原有官汤和维护 Cron 保留，同时新增 `0 12 * * mon`。Cloudflare Cron 使用 [UTC 时间](https://developers.cloudflare.com/workers/configuration/cron-triggers/)。
3. 执行 `npm test`、`npm run lint`、`npm run deploy:dry-run`，用隔离数据库和模拟邮件测试并发、失败、退订、统计边界及管理员权限。
4. 在线检查 `/api/health`、后台预览和下次发送时间。发布时不额外触发作者群发；首次定时发送后可在后台及 Cloudflare Cron 日志确认实际结果。
